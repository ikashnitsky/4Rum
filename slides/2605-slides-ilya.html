Foundation

Two Approaches to Migration

❌ Syntax Translation
Line-by-line conversion
  • • Converts SAS DATA steps → R code mechanically
  • • Produces R that "thinks in SAS"
  • • Fragile — SAS idioms don't map cleanly
  • • Macros encoding business rules are lost
✅ Pipeline Replacement
Rebuild each stage in idiomatic R
  • • Map SAS roles to purpose-built R packages
  • • Tidyverse + domain packages (survey, gt, haven)
  • • Maintainable, reviewable, submission-ready
  • • Pharmaverse proved this at scale

Merck / PharmaSUG 2025

GenAI-Assisted Conversion Workflow

1
Import first — haven::read_sas() to ingest .sas7bdat without rewriting ETL
2
Decompose macros — split into modules (data prep → model → output) and convert each separately; feeding the full macro to an LLM fails
3
Manual parameter verification — replace PROC MIXED → lmer() + emmeans(); check degrees-of-freedom method explicitly
4
Numerical equivalence check — run SAS and R outputs side-by-side; Merck confirmed identical PK summary results
5
Output: use templates — GPT-4o is weak at RTF macros; use existing {r2rtf} templates and adapt

Key Pattern

AGENTS.md — Encoding Institutional Knowledge

The {admiral} package publishes a 1,300-line auto-generated AGENTS.md — a README for AI agents, not humans

What admiral's AGENTS.md contains
ADaM conventions LLMs can't infer — e.g. flag vars take "Y" or NA, never "N"
Full ecosystem pipeline context: sdtm.oak → admiral → xportr → XPT
Unit testing rules, documentation workflow, compliance check comment
DST equivalent would encode
StatBank table format conventions and px-file structure
Eurostat reporting requirements and metadata standards
Survey weighting conventions that an LLM cannot guess

rOpenSci now requires AGENTS.md as a peer-review artifact — this norm is arriving regardless

⚠️ Watch Out

Silent Failure Modes

SAS Macros encode business rules, not syntax
LLM translators handle DATA steps and PROC SQL well but fail silently on macros — macro logic must be interpreted by a human, not translated character by character
Missing values behave differently
In SAS, IF x > 5 where x = . evaluates to FALSE. In R, x > 5 where x = NA returns NA — propagating silently through pipelines. CAMIS working group documents all such discrepancies.
PROC MIXED → lmer() is the hardest step
Kenward-Roger vs Satterthwaite degrees-of-freedom methods differ by default between SAS and R — producing different p-values for the same model. Always verify manually.
haven::read_sas() drops some format labels silently
Always run str() on imported data and cross-check variable types before any analysis step
